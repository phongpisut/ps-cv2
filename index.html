      What is MoQ?

      MoQ (Media over QUIC) is a new protocol for live data, being standardised at the IETF. In the browser it runs over WebTransport (QUIC). Each visitor publishes a broadcast made of named tracks, and a relay forwards every track to whoever subscribes. You send it once and the relay fans it out, so there’s no server code for this game at all.

      How this game uses it

      • state: your fruit and score, every 2 seconds, so everyone sees who’s here.
      • input: your drops, sent to whoever is running the physics.
      • world: the whole board, about 20 times a second, from one visitor (the one who has been here longest with the tab open). If they leave, the next visitor picks up from the newest board.

      Needs WebTransport (Chrome, Edge, Firefox). Other browsers show “offline” and play solo.

      (04) Optimization

      Making mobile feel 60 FPS.

      Two tools I reach for when a React Native screen has to stay smooth. They only exist on phones, so instead of a demo, here’s how they work.

      React Native Skia

      Skia: draw on the GPU, skip the view tree

      Skia is the open-source 2D graphics engine that draws Chrome and Android. React Native Skia (by Shopify) gives JavaScript a canvas backed by it, so charts, gradients, shadows and blur become one GPU surface instead of hundreds of native views.

      • One canvas, one draw pass: no layout or view to create for every point.
      • Animated by Reanimated worklets on the UI thread, so a busy JS thread doesn’t drop frames.
      • Where I used it: Tidjai’s UI and InnovestX’s 60 FPS trading charts.

      Nitro Modules

      Nitro: call native code directly, no bridge

      React Native’s old bridge sent every native call as a JSON message through an async queue. Nitro Modules (by Margelo) are built on JSI: JavaScript holds a direct reference to a native C++ object, so a call is just a function call. It’s synchronous, typed and needs no serialization.

      import type { HybridObject } from 'react-native-nitro-modules'

// one TypeScript spec → Nitrogen generates C++, Swift and Kotlin
export interface Quotes extends HybridObject<{ ios: 'swift'; android: 'kotlin' }> {
  latest(symbol: string): number   // synchronous, no bridge
}
      • The TypeScript spec is the contract. Nitrogen generates the native bindings, so both sides stay typed.
      • No JSON or async hop per call, so it’s cheap enough to call on every frame.
      • Where I used it: InnovestX, for zero-throttle JSI calls on live trading data.

      What is WebAssembly?

      WebAssembly (WASM) is a compact binary format that browsers compile to machine code. Languages like C, C++ and Rust compile to it, so code written for native apps can run in a web page at near-native speed, next to JavaScript.

      1. box3dC source
      2. Emscriptenclang → wasm
      3. box3d.wasmbinary + SIMD
      4. Browsercompiles to machine code
      5. JSworld.step()

      What’s running here

      Box3D is Erin Catto’s 3D physics engine, from the author of Box2D, written in C. This page loads it as box3d.wasm, steps the world 60 times a second and copies every body’s position into three.js.

      What is WebGPU?

      WebGPU is the modern graphics API for the web and the successor to WebGL. Besides drawing, it can run compute shaders: small programs written in WGSL that run on thousands of GPU cores at once.

      1. JavaScript32 bytes: cursor + time
      2. Compute passmoves every particle
      3. Render passdraws the same buffer
      4. Screenno copy back to the CPU

      What’s running here

      Each particle has a home pixel in my name. Every frame a compute shader springs all of them home, pushes them away from your cursor and adds a little swirl. The positions never leave the GPU: the CPU only sends the cursor and the clock.
